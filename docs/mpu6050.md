# MPU6050 六轴传感器

无需修改源码即可试用：见 [组件调试应用](component_demo.md)，通过 menuconfig 配置接线，再使用网页控制和查看状态。

可选模块名 `mpu6050`，接口见 [mpu6050.h](../components/mpu6050/include/mpu6050.h)。模块提供三轴加速度、三轴角速度、芯片温度、原始有符号读数、量程和休眠控制。没有加入 GPS 或蓝牙，也不包含姿态融合、DMP、航向估计或自动校准。

```bash
bash tools/idf.sh --app satellite --modules mpu6050 build
bash tools/idf.sh --app satellite --board XIAO_ESP32_S3_SENSE --modules network,web,camera,mpu6050 build
```

## 接线与资源

应用明确指定 SDA、SCL 的 GPIO 编号，传感器与开发板共地，电源及 I²C 上拉按所用模块规格配置，GPIO 侧电平应为 3.3 V。AD0 低时地址为 `0x68`，高时为 `0x69`。`internal_pullups` 默认关闭；应优先使用合适的外部上拉。默认轮询读取，无需连接 INT 引脚。

当前每个实例拥有一条独立的 I²C 主机总线，创建时登记 SDA/SCL 和控制器；创建失败或销毁后释放。不能用另一组 GPIO 重复申请同一控制器，也不能和其他实例共享此总线。外部应用直接使用 SDK 分配的 I²C 控制器由 SDK 检测占用。

选择摄像头模块时，摄像头的 SDA/SCL 与 SCCB 控制器在资源检查中静态保留，即使摄像头运行时关闭也保留。当前摄像头依赖默认使用 I²C1，因此 MPU6050 默认使用 I²C0；若修改了 `menuconfig` 中的 SCCB 控制器，需相应调整。资源冲突会创建失败，不会更改其他模块的接线。

## 调用示例

应用组件在 `idf_component_register` 后使用 `idf_component_optional_requires(PRIVATE mpu6050)`，代码通过 `CONFIG_MCU_ENABLE_MPU6050` 判断模块是否选中。以下 `APP_*` 参数由应用根据实际接线定义：

```c
#include "mpu6050.h"

mpu6050_config_t config = MPU6050_CONFIG_DEFAULT(APP_IMU_SDA_GPIO, APP_IMU_SCL_GPIO);
config.i2c_port = 0;
config.address = 0x68;
config.accel_range = MPU6050_ACCEL_2G;
config.gyro_range = MPU6050_GYRO_250DPS;

mpu6050_handle_t imu;
ESP_ERROR_CHECK(mpu6050_create(&config, &imu));

mpu6050_sample_t sample;
esp_err_t result = mpu6050_read(imu, &sample);
if (result == ESP_OK) {
    // sample.accel_m_s2[0..2]：X/Y/Z 加速度，单位 m/s²，包含重力。
    // sample.gyro_dps[0..2]：X/Y/Z 角速度，单位 °/s。
    // sample.temperature_c：芯片温度，单位 °C。
    // sample.timestamp_us：读取完成时 MCU 的单调时钟，单位 µs。
}

ESP_ERROR_CHECK(mpu6050_set_sleep(imu, true));
ESP_ERROR_CHECK(mpu6050_set_sleep(imu, false));
ESP_ERROR_CHECK(mpu6050_destroy(imu));
```

创建会检查 `WHO_AM_I=0x68`、复位并配置传感器，耗时约 200 ms；地址改为 `0x69` 时身份寄存器仍应返回 `0x68`。身份不匹配返回 `ESP_ERR_NOT_SUPPORTED`，不写入复位/配置寄存器。没有设备或 I²C 超时则返回底层错误。

| 参数 | 支持范围 / 默认值 |
| --- | --- |
| 加速度量程 | ±2/4/8/16 g；默认 ±2 g |
| 陀螺仪量程 | ±250/500/1000/2000 °/s；默认 ±250 °/s |
| I²C 时钟 | 10～400 kHz；0 使用默认 400 kHz |
| 单次传输超时 | 1～10000 ms；0 使用默认 100 ms |
| `dlpf` | 寄存器 DLPF_CFG 值 0～6；默认配置宏为 3 |
| `sample_rate_divider` | 寄存器 SMPLRT_DIV 值 0～255；默认配置宏为 9 |

默认配置使用 1 kHz 内部采样基准，经 `1 + 9` 分频得到 100 Hz。DLPF=0 时陀螺仪基准为 8 kHz，加速度更新仍受传感器自身速率限制；根据芯片资料选择滤波和采样参数。`read` 一次连续读出 14 字节，保持六轴及温度属于同一采样快照；它不等待新数据，不进行后台采样，也不做 FIFO 缓冲。调用快于传感器更新速度可能重复读取同一帧，调用过慢则只得到最新帧。

`raw_accel`、`raw_gyro`、`raw_temperature` 保留原始有符号数，换算使用创建时设置的量程。错误或休眠时不会修改调用者的输出结构；休眠期间读取返回 `ESP_ERR_INVALID_STATE`，唤醒后等待约 100 ms 再允许读取。温度是芯片温度，不能直接当作精确环境温度。

接口以实例互斥锁串行执行，供普通任务调用；不适合 ISR，初始化和唤醒也不应放进要求立即响应的 HTTP 处理函数。销毁前由应用停止其他使用者；`destroy` 释放总线，不隐式改变传感器供电状态，需要休眠时先调用 `set_sleep`。

## 验证与资料

本机测试编译实际驱动，覆盖 16 种量程组合、负数和边界读数、温度换算、AD0 地址、身份不匹配、各初始化阶段失败清理、休眠、I²C 超时，以及摄像头控制器/GPIO/跨模块冲突。已验证单独构建和与摄像头等模块组合构建；实际静止偏差、安装方向、振动与噪声需要上板验证。

寄存器依据 TDK/InvenSense 的 [MPU-6000/MPU-6050 Register Map](https://invensense.tdk.com/wp-content/uploads/2015/02/MPU-6000-Register-Map.pdf)，电气与测量规格见 [产品规格书](https://product.tdk.com/system/files/dam/doc/product/sensor/mortion-inertial/imu/data_sheet/mpu-6000-datasheet1.pdf)。
